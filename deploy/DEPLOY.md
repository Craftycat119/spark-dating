# Запуск COFI на своём сервере

Эта инструкция ведёт от покупки сервера до работающего сайта с https, мини-приложением в Telegram и звонками
через мобильный интернет. Всё ставится одной командой, а ниже подробно описано, что она делает и зачем.

---

## Как это устроено

```
 Телефон / браузер / Telegram
            │  https://ваш-домен (порт 443)
            ▼
   ┌───────────────────┐      сертификат Let's Encrypt (бесплатный, продлевается сам)
   │       nginx       │◄──── шифрование https, ограничение частоты запросов
   └────────┬──────────┘
            │  http://127.0.0.1:8000 (только внутри сервера)
            ▼
   ┌───────────────────┐      systemd следит, чтобы приложение всегда работало
   │   COFI (Python)   │───── база и файлы: /var/lib/cofi
   └────────┬──────────┘
            │  api.telegram.org — вход, уведомления, звонки
            ▼
        Telegram-бот

 Звонок: телефон ◄────── напрямую, если получается ──────► телефон
         телефон ◄──── через coturn (порт 3478/5349) ────► телефон, если оператор не пускает напрямую
```

**Почему так, а не просто `python run.py`:**

| Деталь | Зачем |
|---|---|
| **Домен и https** | Без https браузер не даёт камеру, микрофон и геопозицию, Telegram не открывает мини-приложение, а пароли и переписка шли бы открытым текстом |
| **nginx впереди** | Принимает https и передаёт запросы приложению. Он быстрее и надёжнее отдаёт файлы, держит тысячи соединений и не пускает к приложению напрямую |
| **Приложение слушает только 127.0.0.1** | Снаружи до него не достучаться в обход nginx и https |
| **systemd** | Запускает COFI при старте сервера и сам перезапускает его при сбое за 3 секунды. Не нужно держать открытое окно терминала |
| **Отдельный пользователь `cofi`** | Даже если в приложении найдётся ошибка, через неё нельзя получить права администратора сервера. Приложение может писать только в свою папку данных |
| **coturn (TURN)** | Мобильные операторы обычно не пропускают прямое соединение между телефонами. TURN пересылает звук и видео. Свой TURN бесплатный и не зависит от Metered |
| **Файрвол** | Открыты только нужные порты: вход по SSH, сайт и TURN. Всё остальное закрыто |
| **Резервные копии** | Каждую ночь копируются база и файлы, хранятся 14 дней. Если что-то сломается или удалится, данные можно вернуть |

## Шаг 1. Купить сервер

Подойдёт любой VPS в России (152-ФЗ требует хранить персональные данные граждан РФ в России):
Timeweb Cloud, Selectel, Yandex Cloud, VK Cloud, REG.RU.

- **Система:** Ubuntu 24.04 (или 22.04).
- **Размер:** 2 vCPU, 4 ГБ памяти, 40–50 ГБ диска. Хватит и 2 ГБ памяти: скрипт сам добавит подкачку.
- **Публичный IPv4** обязателен (обычно есть по умолчанию).

После покупки хостинг пришлёт **IP-адрес** и **пароль root** (или попросит добавить SSH-ключ).

## Шаг 2. Купить домен и направить его на сервер

1. Купите домен, например `cofi-app.ru` (reg.ru, nic.ru или у того же хостинга).
2. В настройках DNS домена добавьте **A-запись**: имя `@` (сам домен) → IP вашего сервера.
3. Подождите 5–30 минут. Проверить можно в PowerShell: `nslookup cofi-app.ru` — должен показаться IP сервера.

**Зачем:** сертификат https выдают только на домен, который действительно указывает на ваш сервер.

## Шаг 3. Подключиться к серверу

В PowerShell на своём компьютере:

```powershell
ssh root@IP-сервера
```

Первый раз спросит «Are you sure…» — напишите `yes`, затем пароль (символы при вводе не видны, это нормально).

## Шаг 4. Загрузить проект на сервер

**Вариант А: с GitHub** (удобно обновлять):

```bash
apt-get update && apt-get install -y git
git clone -b cofi https://github.com/Craftycat119/spark-dating.git
cd spark-dating
```

Если репозиторий приватный, GitHub попросит логин и **токен** вместо пароля (github.com → Settings → Developer settings → Personal access tokens).

**Вариант Б: архивом с вашего компьютера.** В PowerShell на своём компьютере (не на сервере):

```powershell
scp C:\Users\Алёна\Downloads\cofi.zip root@IP-сервера:/root/
```

И на сервере:

```bash
apt-get update && apt-get install -y unzip && unzip cofi.zip && cd cofi
```

## Шаг 5. Запустить установку

```bash
sudo bash deploy/install.sh
```

Скрипт задаст 4 вопроса:

| Вопрос | Что ответить |
|---|---|
| Домен сайта | `cofi-app.ru` (без https://) |
| Почта для сертификата | Ваша почта. Let's Encrypt напишет, если сертификат почему-то не продлится |
| Почта администратора | Почта, под которой вы войдёте в админ-панель |
| Токен Telegram-бота | Токен от @BotFather или Enter, чтобы вписать позже |

Установка идёт 3–7 минут. В конце появится «Готово. COFI: active» и адрес сайта.

## Шаг 6. Закончить настройку

1. **Почта для кодов.** Откройте настройки: `sudo nano /opt/cofi/.env`, заполните блок SMTP (для Яндекса:
   `SMTP_HOST=smtp.yandex.ru`, `SMTP_USER` и `SMTP_FROM` — ваш адрес, `SMTP_PASSWORD` — пароль приложения).
   Сохранить: `Ctrl+O`, Enter, выйти: `Ctrl+X`. Применить: `sudo systemctl restart cofi`.
   Проверить: `cd /opt/cofi && sudo -u cofi venv/bin/python -m app.cli test-email ваш@ящик`.
2. **Telegram.** Кнопка «Меню» в боте сама начнёт вести на `https://ваш-домен` после запуска сервера (в @BotFather ничего менять не нужно).
   Главное — чтобы этот бот больше нигде не был запущен: выключите сервер и туннель на домашнем компьютере, иначе бот будет отвечать с двух мест (ошибка 409).
   Группы для заявок: добавьте бота в группу и впишите её id в `TELEGRAM_ADMIN_CHAT_ID` и `TELEGRAM_SUPPORT_CHAT_ID`.
3. **Проверка.** Откройте сайт с телефона, зарегистрируйтесь, позвоните с другого телефона через мобильный интернет.

## Что именно делает install.sh, по шагам

**0. Проверки.** Скрипт убеждается, что запущен от администратора и на Ubuntu, и сверяет, что домен указывает на IP
сервера. Если нет, предупреждает: иначе не получится выпустить сертификат.

**1. Пакеты.** Ставит Python, nginx, certbot (сертификаты), coturn (TURN), ufw (файрвол), sqlite3 (резервные копии базы).
Если памяти меньше 3 ГБ, добавляет **файл подкачки 2 ГБ**: установка OpenCV и проверка лица требуют памяти,
и без подкачки процесс на маленьком сервере может упасть.

**2. Пользователь и папки.** Создаёт системного пользователя `cofi`, у которого нет пароля и входа на сервер.

| Папка | Что там | При обновлении |
|---|---|---|
| `/opt/cofi` | код приложения и его окружение `venv` | заменяется |
| `/opt/cofi/.env` | настройки и секреты | **не трогается** |
| `/var/lib/cofi` | база `spark.db`, фото, видео, кружочки, модели для проверки лица | **не трогается** |
| `/var/backups/cofi` | резервные копии | пополняется каждую ночь |

Код и данные разделены специально: обновление кода не может задеть анкеты и переписки.

**3. Python-окружение.** Отдельное окружение `venv` только для COFI, чтобы версии библиотек не конфликтовали с системными.

**4. Настройки.** Создаёт `/opt/cofi/.env` с безопасными значениями:
- `DEV_MODE=0` — никаких кодов на экране, только на почту;
- `COOKIE_SECURE=1` — cookie входа передаётся только по https;
- `SECRET_KEY` — случайные 64 символа, ими подписываются коды и сессии;
- пароль для TURN — случайный.

Права на файл `600`: прочитать его может только пользователь `cofi`. Если файл уже есть (повторный запуск),
скрипт его не перезаписывает.

**5. Служба systemd** (`/etc/systemd/system/cofi.service`). Запускает `python run.py` от пользователя `cofi`
на `127.0.0.1:8000` и перезапускает при сбое. Дополнительная защита: `ProtectSystem=strict` (вся система только
для чтения), `ReadWritePaths=/var/lib/cofi` (писать можно только в папку данных), `NoNewPrivileges` (нельзя
получить новые права).

**Почему один процесс, а не несколько:** счётчики попыток входа, соединения для сообщений и звонков и Telegram-бот
живут в памяти процесса. На старте одного процесса хватает на сотни людей одновременно.

**6. nginx и https.** Конфигурация `/etc/nginx/sites-available/cofi`:
- передаёт запросы приложению и **WebSocket** (сообщения в реальном времени и звонки), держит его до часа без обрывов;
- разрешает загрузку файлов до 64 МБ (видео и кружочки);
- передаёт приложению настоящий IP посетителя. Заголовок от посетителя перезаписывается, поэтому подделать его нельзя;
- ограничивает 20 запросов в секунду с одного IP. Это второй рубеж защиты после ограничений в самом приложении;
- скрывает версию nginx.

Затем `certbot` выпускает бесплатный сертификат Let's Encrypt, дописывает https в конфигурацию, включает
переадресацию с http на https и сам продлевает сертификат каждые ~60 дней.

**7. TURN (coturn)** — `/etc/turnserver.conf`:
- порт **3478** (UDP и TCP) и **5349** (TLS, на случай сетей, где пускают только шифрованный трафик);
- звук и видео идут через порты **49160–49200**;
- вход по логину `cofi` и паролю из `.env`, чтобы вашим TURN не пользовались чужие;
- запрещено пересылать трафик на внутренние адреса (127.x, 10.x, 192.168.x и т.д.), чтобы через TURN нельзя было
  добраться до самого сервера или локальной сети хостинга;
- квоты: не больше 12 одновременных каналов на пользователя.

Для TLS нужен тот же сертификат, что у сайта. coturn не может читать файлы Let's Encrypt напрямую, поэтому скрипт
добавляет хук: при каждом продлении сертификат копируется для coturn, и тот перезапускается.

**8. Файрвол (ufw).** Открыты: SSH (22), сайт (80, 443), TURN (3478, 5349, 49160–49200/udp). Всё остальное закрыто.
SSH открывается первым, чтобы вы не потеряли доступ к серверу.

**9. Резервные копии.** Каждую ночь в 04:15 команда `/usr/local/bin/cofi-backup`:
- копирует базу через `sqlite3 .backup` (корректно, даже пока сайт работает);
- упаковывает фото и видео в архив;
- удаляет копии старше 14 дней.

Резервные копии лежат на том же сервере. Для защиты от потери всего сервера раз в неделю скачивайте их к себе:
`scp root@IP:/var/backups/cofi/* .` или включите снимки (snapshots) в панели хостинга.

## Повседневные команды

| Задача | Команда |
|---|---|
| Статус | `sudo systemctl status cofi` |
| Журнал в реальном времени (входы, ошибки, Telegram) | `sudo journalctl -u cofi -f` |
| Перезапуск после правки `.env` | `sudo systemctl restart cofi` |
| Изменить настройки | `sudo nano /opt/cofi/.env` |
| Обновить приложение (GitHub) | `cd ~/spark-dating && git pull && sudo bash deploy/update.sh` |
| Обновить приложение (архив) | распакуйте новый архив поверх папки проекта и `sudo bash deploy/update.sh` |
| Резервная копия сейчас | `sudo cofi-backup` |
| Создать админа | `cd /opt/cofi && sudo -u cofi venv/bin/python -m app.cli create-admin --name "Оля" --email olya@mail.ru --password Secret123` |
| Проверить почту | `cd /opt/cofi && sudo -u cofi venv/bin/python -m app.cli test-email ваш@ящик` |
| Статус TURN | `sudo systemctl status coturn` |
| Проверить сертификат | `sudo certbot certificates` |

**update.sh** делает резервную копию, копирует новый код (без `.env` и данных), ставит новые зависимости,
перезапускает COFI и проверяет, что он отвечает. Если не отвечает, показывает последние строки журнала.
Новые поля в базе добавляются сами при запуске, анкеты сохраняются.

## Восстановление из резервной копии

```bash
sudo systemctl stop cofi
sudo cp /var/backups/cofi/db-2026-11-05.sqlite /var/lib/cofi/spark.db
sudo tar -xzf /var/backups/cofi/media-2026-11-05.tar.gz -C /var/lib/cofi
sudo chown -R cofi:cofi /var/lib/cofi
sudo systemctl start cofi
```

## Если что-то не работает

| Признак | Причина и что делать |
|---|---|
| Сайт не открывается | `sudo systemctl status cofi nginx`. Если домен только что купили, подождите, пока он начнёт указывать на сервер |
| «Сертификат не выпущен» | Домен ещё не указывает на IP сервера. Проверьте A-запись и запустите `sudo certbot --nginx -d ваш-домен` |
| 502 Bad Gateway | nginx работает, а COFI нет: `sudo journalctl -u cofi -n 50` покажет ошибку |
| Коды не приходят на почту | Не заполнен SMTP в `.env` или неверный пароль приложения: проверьте `test-email` |
| Звонок висит на «Соединяем…» | `sudo systemctl status coturn`. В панели хостинга проверьте, что их файрвол не закрывает порты 3478, 5349 и 49160–49200/udp |
| Telegram-бот молчит | Неверный `TELEGRAM_BOT_TOKEN` или этот же токен запущен где-то ещё (например, на домашнем компьютере). Один токен — один сервер |
| Не входит по SSH после установки | ufw открывает SSH до включения. Если вы сменили порт SSH, откройте его: `ufw allow НОМЕР/tcp` через консоль в панели хостинга |

**Важно:** после переезда на сервер остановите COFI и cloudflared на домашнем компьютере. Иначе бот с тем же токеном
будет получать сообщения то там, то здесь.
